# Share-Link previews are text-only and opacity-preserving

A Share Link pasted into a messenger shows a per-link preview — the Video title (and description) or the Folder name — injected as Open Graph / Twitter meta into the server-rendered shell for `/v/...` and `/f/...`, so links are distinguishable instead of all rendering the same generic card. We deliberately emit **no `og:image`**: a poster frame in the preview would be fetched by every link-preview crawler, and the server-side unfurlers (Telegram, Slack, Discord, Facebook) cache it on their own infrastructure, putting a frame of the Operator's Video on a third party — whereas the on-device fetchers (iMessage, WhatsApp, Signal) embed it only in the end-to-end-encrypted message. Since we cannot reliably serve the image to only the private fetchers, we serve it to none; the title alone makes links distinguishable and leaves nothing visual to cache. This is a bounded exception to ADR-0002's opacity: only a Ready, non-expired, **unprotected** target gets a real title (and its poster is already public at its own URL for anyone holding the link, so the title reveals no more than opening it would), while an unknown, expired, deleted, protected, or still-Processing link falls back to the untouched generic shell — so a crawler still cannot tell those apart, and a protected Video never leaks its title.
